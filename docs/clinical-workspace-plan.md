# 临床工作区调整方案与本地实现记录

日期：2026-11-26。范围：本地代码、文档与验收。本轮没有提交、推送 GitHub 或更新阿里云。

## 设计目标

医生进入系统后先看到患者待办和下一步操作。科研图表和系统维护保留在管理员辅助区域。沿用现有绿色、暖纸色及深浅主题，不改变模型算法、风险阈值或数据库结构。

这一轮完成信息架构与工作流调整。它不构成医疗产品合规认证、模型外部验证或真实临床可用性验证。

## 逐页调整及后续建议

| 页面 | 本轮实现 | 下一步建议 |
| --- | --- | --- |
| 全局导航 | 医生一级入口收敛为工作台、患者档案、评估报告、复查随访；管理员增加系统管理；底部评估说明，顶栏个人账号 | 后续以真实医生任务验证名称和操作路径，避免继续扩展一级菜单 |
| 顶栏 | 移除常驻 AUC；服务在线同时要求健康状态、模型及数据库可用 | 可增加故障发生时间和重试状态，避免短暂初始加载被误认持续故障 |
| 工作台 | 四类主要待办卡片；完整授权范围内的队列、风险辅助排序、阶段筛选和分页；复查与累计统计降为辅助 | 增加负责人、逾期、预计操作时长等，需要先定义真实业务规则 |
| 患者档案 | 保留患者检索、新建和授权；批量导入改为次级操作入口 | 明确患者去重与合并流程，增加授权到期机制，不能仅凭同名自动合并 |
| 接诊与评估 | 显示患者、就诊和指标阶段；实测与填充数量、评估时间、模型版本、人工记录分开；输入变更提示；缺失字段按需展开 | 增加逐项标本采集时间、来源、录入者和数据更新记录；复制历史指标需要明确确认 |
| 医生复核 | 模型结果与医生结论分开；暂不发布继续保留观察状态，允许继续补录、评估和复核 | 终态复核后的更正流程需单独设计；不能将未发布记录提示为“撤销报告”后才能更正 |
| 评估报告 | 一级入口使用“评估报告”；保留快照、下载、撤销与追踪 | 完整设计更正版本、撤销原因和患者可见性提示，撤销操作仍应受权限约束 |
| 复查随访 | 统一入口名称，保留已有预约、待诊、号源与评价功能 | 先确认实际复查业务；随访应围绕复查任务、责任医生、到期、结果回收，不应仅靠预约功能代替 |
| 评估说明 | 新增适用范围、时点、填充、阈值、版本和可展开的内部验证局限 | 维护部署版本与研究产物的发布清单，明确版本适用人群、监测及撤回条件 |
| 系统管理 | 账号、医生申请审核、审计与备份集中；通过辅助链接进入科研与维护 | 可按职责细分运维、账号审核、科研权限；当前沿用既有 admin/doctor 角色模型 |
| 科研与维护 | 新增管理员总入口，研究验证与数据治理保留完整页面；从临床主菜单退出 | 科研指标应追溯具体数据集和运行版本，不能作为每位患者的准确率或当前发布版本的验证证明 |

## 待办口径

队列涵盖可访问、未发布、活动患者的就诊；全部统计后筛选，再分页。统计不再受旧接口最近 8 条记录限制。默认每页 20 条。

| 阶段 | 判定与操作 |
| --- | --- |
| 待补录 | 没有匹配当前输入的有效预测，且存在缺失或无效指标；补录或修正指标 |
| 待运行评估 | 指标完整，没有匹配当前输入的有效模型结果；运行评估 |
| 待医生复核 | 当前输入与有效预测匹配；即使模型使用缺失填充，也需进入复核而不是无限停留补录 |
| 待发布核对 | 已完成有效复核，当前输入与预测匹配；完成独立发布检查后才能发布 |
| 暂不发布 | 当前预测最近一次复核为继续观察且输入仍匹配；展示理由，允许继续处理 |
| 记录待核对 | 已复核但当前草稿与预测不匹配或包含无效输入；不得显示为可直接发布 |

个人草稿值替换已保存输入，与编辑器行为一致；不能把空草稿自动合并旧实测，也不能把其他医生的草稿当成本人输入。历史复核只有关联当前预测时才影响待办阶段。人工记录不显示模型概率或模型风险等级。

有效当前模型结果按高、中、低风险辅助排序，同风险按就诊时间倒序；排序不改变业务阶段。队列显示缺失和需修正数量，避免把非法值计为实测。

加载中、请求失败、确实为空分别显示。失败时不回退为零待办；待办和累计统计的失败状态独立，可以分别重试。

## 模型说明的表达边界

- 35 项包含术前、术中、入 ICU 和术后指标；不能把这组输入的结果描述为纯术前预测。
- 当前系统没有逐项采样时间，页面明确要求结合原始病历核对，不能伪造精确时点。
- 缺失项使用训练中位数填充，填充值不属于患者实测值。
- 风险阈值和版本从当前模型资产读取；已有患者评估显示其自身保存的预测时间与版本。
- 内部验证摘要读取项目所附 `Voting Ensemble` 行，避免取其他模型的最大 AUC 冒充当前集成模型指标。产物缺失时显示未提供。
- 随附研究结果与当前部署指纹尚未通过发布清单建立可证明的对应关系；页面明确其不是当前部署的外部验证。

- 暂不发布记录可继续编辑、重新运行模型和再次复核；重新评估清除旧复核状态，重新提交观察意见并刷新后仍可继续处理。该路径已在最终生产构建中复测。
- 工作台在 390×844 视口下无页面横向溢出，已检查深色切换的 DOM 主题状态；浏览器采集未发现控制台错误。
- 项目指定的 `vision.js` 脚本在本机缺失，本轮未完成截图识图与逐像素视觉验收，不能将 DOM/布局尺寸检查等同于完整视觉验收。
- 本机既有 Python 环境仍出现 scikit-learn 1.9.1 与资产 1.9.0、XGBoost 序列化版本警告；测试通过不等于版本兼容性已经解决。上线前需在与模型一致的环境再验收。

## 建议下一轮优先级

1. 完成指标采样时点与来源字段、输入变更追踪、复制指标确认，以及终态复核后的更正路径。
2. 统一医院业务时区。旧汇总接口的“今日复查预约”仍按 UTC 日期统计；中国时区跨日时可能与浏览器日期不同，需在下一轮统一服务端和前端口径并增加跨日测试。
3. 为较大业务量优化队列。目前一条数据库查询取出授权范围内未完成记录，在内存判定阶段、统计与分页；尚无按状态持久化或数据库侧分页优化。
4. 以真实工作情景评估复查随访，收敛目前混合预约、号源和评价的页面；再决定是否拆分。
5. 生成发布清单，把模型、校准器、依赖锁定、验证结果和部署指纹关联；完成一致环境、浏览器视觉与医生可用性验收后再发布。
