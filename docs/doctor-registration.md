# 医生注册与审核

登录页的“申请医生账号”打开 `/register`。填写姓名、账号、医院、科室和至少 12 位密码后提交。申请人需联系系统管理员查询审核结果；重复账号与重复申请返回相同受理提示，避免公开账号是否存在。

管理员登录后，在“账号与审计 → 医生注册审核”核实身份。选择“核实并开通”后，申请人可使用自设密码登录，角色固定为医生。不予通过时必须填写原因；申请人需要联系管理员处理后续开通，不能自行覆盖已审核申请。

申请资料独立保存于 `doctor_applications` 表，数据库版本升级至 5。未审核的申请不会创建员工账号，也不能访问患者资料。密码只保存哈希，审核结束后从申请表清除；审核动作与备注写入审计日志。审核接口沿用管理员权限和 CSRF 检查，重复审核返回 409。

公开申请接口采用每个来源 IP 每 15 分钟最多 5 次的限流。反向代理应正确传递可信来源 IP，不要将客户端随意提供的代理头视为可信身份。

已有数据库启动时自动添加申请表；既有员工、患者和报告表保留。部署前照常备份数据库。更新仓库后，云服务器仍需单独构建和部署。

验证命令：

```powershell
.venv/Scripts/python.exe -m pytest tests/test_doctor_registration.py -q
```

前端检查沿用 `frontend/package.json` 中的 build 脚本（Vue TypeScript 检查与 Vite 生产构建）。本地运行前后端后，可从 `/login` 和 `/register` 检查入口与申请流程。
